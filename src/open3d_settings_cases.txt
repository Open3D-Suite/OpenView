# The shared cases of what every OPEN3D app shares: the language preference and the folders of each
# app. The tests of its three implementations (open3d_settings.rs, open3d_settings.py and
# open3d_settings.cpp) all read this file: on the same input the three must give the same answer.
# The contract is common/settings.md in the OPEN3D root; this file is a copy of
# common/settings/open3d_settings_cases.txt there.
#
# One case per line, its fields separated by "|", the spaces around a field left out. Empty lines and
# lines that start with "#" are not cases.
#
#   windows | LANGID | language
#       The language of Windows (D-052): the LANGID that GetUserDefaultUILanguage gives, in
#       hexadecimal, and the language shown when there is no preference.
#   read | settings.json | LANGID | preference | language
#       Reading a settings.json: the preference it holds (en, es, or none) and the language shown
#       with that language of Windows.
#   write | settings.json before | language written | settings.json after
#       Writing en, es or none (taking the preference out) into a settings.json, and the file
#       afterwards, compared as JSON: the same keys with the same values, whatever the spaces and
#       the order of the keys.
#   folders | app | OPEN3D_SETTINGS_DIR | APPDATA | OPEN3D_DATA_DIR | LOCALAPPDATA | settings | data
#       The folders of an app (D-042, D-044): the folder of its settings and the folder of
#       everything else it writes, from the four variables. A variable is "(unset)", "(empty)" or
#       its value; a folder is "(none)" or its parts, separated by "/".
#   carry | old folder | new folder | what it does
#       Carrying an app's old folder over to its new one (D-048, D-049): what the two hold before,
#       and what carry_over does: "nothing", or "copied N" (N files copied, nothing left out). When
#       it copies, the new folder then holds exactly what the old one holds; otherwise it is as it
#       was. The old folder is always left as it was, nothing else is left beside the new one, and
#       a second time does nothing. A folder is "(none)" when nothing has its name, "(file)" when a
#       file has it, "(empty)", or its entries separated by ";": "name=text" is a file holding
#       that text, "name/" an empty folder, and a "/" inside a name puts it in a folder.
#
# A settings.json is "(no file)", "(empty)" or the bytes of the file, written as text where \n, \r,
# \t, \\ and \xHH (one byte, in hexadecimal) are escapes.
